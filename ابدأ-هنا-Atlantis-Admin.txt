ATLANTIS — تحديث لوحة الإدارة + الشحن + الطلبات
=========================================

مهم: لا تمسح مجلد GitHub Desktop ولا مجلد .git. هذا التحديث لا ينقل الأسعار التجريبية إلى قاعدة البيانات باعتبارها أسعارًا حقيقية.

الخطوات بالترتيب:

1) افتح Supabase > مشروع Atlantis > SQL Editor > New query.
   افتح ملف SUPABASE_STEP2.sql من هذه الحزمة باستخدام Notepad (كليك يمين > Open with > Notepad).
   انسخ محتوى الملف كله والصقه في SQL Editor واضغط Run.
   يجب أن تظهر Success. هذا ينشئ shipping_zones و orders و supply_requests، ويضيف أعمدة الفيسبوك واللوجو ومعلومات عرض السعر.
   لا يعيد إنشاء admin_users ولا يمسح المنتجات الموجودة.

2) خذ نسخة احتياطية من مجلد مشروع Atlantis المحلي.

3) بعد نجاح SQL فقط: افتح GitHub Desktop > Repository > Show in Explorer.
   المجلد الصحيح يحتوي على package.json و src و public.

4) افتح محتويات ZIP في مجلد منفصل. انسخ الملفات والمجلدات من داخله إلى مجلد المشروع المحلي، واختر Replace للملفات المتكررة.
   مهم: لا تضع مجلدًا باسم Atlantis-Full-Admin داخل المشروع. انسخ محتوياته.

5) في GitHub Desktop > Changes: راجع التغييرات. Summary: Activate Atlantis admin, shipping and orders
   اضغط Commit to main ثم Push origin.

6) افتح Vercel > مشروع Atlantis > Deployments. انتظر ظهور Ready. إن ظهر Error اقرأ Build Logs ولا تفترض نجاح النشر.
   متغيرا البيئة اللذان أضفتهما من قبل يكفيان:
   NEXT_PUBLIC_SUPABASE_URL
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY

7) افتح https://atlantis-supplies.vercel.app/ar/staff-login
   سجل الدخول بنفس الإيميل والباسورد الذي أنشأته في Supabase Authentication Users والموجود في admin_users.

8) من لوحة الإدارة:
   - Settings: راجع رابط Facebook، ارفع اللوجو إن أردت تغييره ثم Save.
   - Shipping: أضف المنطقة (المحافظة أو المدينة) والسعر أو اختر "بعد المراجعة".
   - Categories: أضف القسم الحقيقي.
   - Products: أضف المنتج الحقيقي وسعره وصوره؛ الشرائح حسب الكميات.
   - Orders: تابع طلبات الشراء التي تم حفظها عبر الموقع، وعدّل حالتها وشروط الدفع.
   - Supply Requests: تابع طلبات التوريد وعدّل حالتها.
   - Quotations: احفظ عرض السعر وشروطه على طلب التوريد (لا يتم إرساله أوتوماتيكيًا).
   - Customers: قائمة مجمعة من الطلبات والتوريدات الحقيقية.

9) افتح الواجهة العامة، جرّب منتجًا حقيقيًا ثم أكمل طلب اختبار باستخدام بيانات اختبار لا تخص عميلًا حقيقيًا.
   تأكد من وصوله إلى Orders ثم جرّب طلب توريد ووصوله إلى Supply Requests.

ملاحظات مهمة:
- المنتجات القديمة "DEMO" تظل معروضة وموسومة بوضوح حتى تفعّل خيار Publish Catalog من إعدادات المدير. أسعارها توضيحية وليست أسعارك الحقيقية.
- أضف كل الأقسام والمنتجات الحقيقية أولًا مع ترك خيار Publish Catalog مغلقًا في Admin > Settings. بعد اكتمال البيانات، فعّل Publish Catalog ثم اضغط Save؛ عندها فقط تنتقل الواجهة العامة إلى بيانات Supabase.
- لا يوجد دفع إلكتروني. اتفاق الدفع وتأكيد الطلب يتمان مع مسؤول المبيعات.
- العملاء يتقدمون بطلب من دون تسجيل حساب. حساب العميل وتتبع طلباته عبر كلمة مرور غير مفعّلين.
- اللوجو في الهيدر والفوتر قابل للتغيير من Settings. أيقونة تبويب المتصفح ما زالت ملفًا داخل الموقع.
- عروض أسعار التوريد تُحفظ لدى المدير، ولا تُرسل تلقائيًا للعملاء.
- الملفات اجتازت اختبار صياغة TS/TSX ومسارات الاستيراد وبعض اختبارات قواعد الأسعار. لم يُنفذ npm run build كاملًا لأن تثبيت مكتبات npm لم يكن متاحًا في بيئة الإنشاء. اختبار Vercel النهائي مطلوب قبل الاعتماد على الموقع.

استرجاع سريع في حال فشل التحديث:
- GitHub Desktop > History ثم ارجع إلى آخر Commit ناجح من نسختك السابقة، أو استعد نسخة المجلد الاحتياطية.
- راجع Vercel Build Logs قبل اتخاذ خطوة الاسترجاع.
- لا تحذف جداول Supabase التي تم إنشاؤها.
